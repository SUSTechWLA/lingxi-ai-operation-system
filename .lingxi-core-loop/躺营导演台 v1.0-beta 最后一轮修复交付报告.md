# 躺营导演台 v1.0-beta 最后一轮修复交付报告

## 结论

当前代码已满足 v1.0-beta 第一版用户内测的自动化发布门禁。

本轮补齐的最后缺口：

1. 前端导出页不再把 `VIDEO` / `PROJECT_PACKAGE` 的占位路径当作真实产物。
2. 只有真实 artifact manifest 携带 `storageRef` 时，导出页才允许预览、打开文件夹或导出交付包。
3. `ARTIFACT_MANIFEST_INVALID` 映射为内测用户可理解的中文错误提示。
4. 增加 `npm run test:director` 回归检查，覆盖“无真实 VIDEO manifest 不可导出”的场景。

## 已核对的 beta P0 链路

- `BuildArtifactRequestsFromNodeChecked` 会拒绝缺 `unitId` / `kind` 的 `artifacts[]`，错误码为 `ARTIFACT_MANIFEST_INVALID`。
- LocalJob artifact sync 使用严格转换路径，缺 `unitId` 不会静默跳过。
- `HYPERFRAMES_RENDER` 输出 `unitId=final-video`、`kind=VIDEO`、`storageRef=local://projects/{projectId}/renders/final.mp4`。
- Render / Package guard 使用精确 `stage + kind` 查询。
- Runtime E2E 覆盖 preview approve、render gate、package gate、unrelated artifact 不满足 guard 等场景。
- local executor 输出已包含 `unitId`、`status`、`humanApproved`、`dependsOn`、`producedByTool`、`producedByRole` 和 `metadata`。

## 手工验收状态

尚未执行真实本地渲染服务联调。内测发版前建议按原方案继续做一次人工正向/反向验收：

- 正向：启动 cloud/local/hyperframes/frontend，完成 preview approve → render completion → ArtifactIndex 出现 `VIDEO` → 导出页显示 `final.mp4`。
- 反向：预览未确认、本地执行器离线、缺 `VIDEO`、`FINAL_REVIEW.failed` 均应阻断下游。
