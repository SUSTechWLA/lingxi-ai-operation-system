# 下一步系统优化完整解决方案：受限自主规划 + 按需知识检索 + 事实注入口播生成

## 1. 优化目标

当前问题不是单纯“新闻搜索工具没生效”，而是系统缺少一套**知识使用决策机制**：

```text
用户输入
  ↓
判断是否需要新事实
  ↓
决定是否调用新闻搜索
  ↓
把新闻结果整理成事实包
  ↓
把事实包注入 proposal / script
  ↓
生成可追溯、有时效性的口播
```

你的仓库 README 已经把系统定位为视频创作 Agent，并写明云端核心是 `Dynamic Agent Runtime: Planner → Guard → Compiler → DAG`，说明架构方向已经具备自主规划基础。([GitHub][1])
架构文档也写明 `agentruntime` 的职责是 `LLMPlanner → PlanGuard → PlanCompiler → Transient DAG`，入口为 `/api/agent/runs`。([GitHub][2])

所以这次优化不应该继续只改某一个 YAML，而应该升级为：

> **让 AI 自主规划是否需要检索，但由后端 Guard 强制控制检索边界。**

# 2. 当前系统现状判断

## 2.1 已有能力

你当前已经具备这些基础：

| 能力                    | 当前状态 | 说明                                                                       |
| --------------------- | ---- | ------------------------------------------------------------------------ |
| Dynamic Agent Runtime | 已有   | 架构文档已明确 Planner / Guard / Compiler / DAG                                 |
| AgentPlan             | 已有   | `AgentPlan` 已包含 `Goal / Domain / Mode / Steps / Budget / StopPolicy`     |
| PlanGuard             | 已有   | 已校验工具存在性、参数、依赖、风险、成本、阶段约束                                                |
| PlanCompiler          | 已有   | 能把 AgentStep 编译为 DAG 节点，并支持质量门禁                                          |
| ToolManifest          | 已有   | 工具声明支持 `capabilities / tags / costLevel / riskLevel / qualityPolicy` 等字段 |
| Review Gate           | 已有   | 当前视频 pipeline 已有 proposal、script、composition、preview 等人工审核点              |

`AgentPlan` 当前结构包含 `Goal / Domain / Mode / Steps / Budget / StopPolicy`，但还没有表达“是否需要外部知识 / 是否必须检索 / 用什么知识类型”。([GitHub][3])
`PlanGuard` 当前已经能校验步骤、工具存在性、依赖顺序、参数类型、成本、风险和阶段约束，所以它适合作为“搜索是否允许”的硬规则层。([GitHub][4])
`PlanCompiler` 当前已经能把步骤编译成 DAG，并且能自动插入质量检查节点和质量门禁。([GitHub][5])

## 2.2 当前短板

当前固定 pipeline 的 `proposal_exec` 和 `script_exec` 都直接调用 `video_script_generator`，中间没有 `news_search / knowledge_pack / fact_extract` 节点。([GitHub][6])

所以现在的问题是：

```text
新闻工具可能存在
但没有进入 AgentPlan
也没有进入 DAG
更没有进入 video_script_generator 的 prompt
```

最终表现就是：

```text
用户问“佛得角世界杯出线”
系统仍然基于旧知识生成“差点出线、仍在追梦”
```

# 4. 核心设计：KnowledgePolicy

## 4.1 新增知识策略模型

建议在 `cloud-backend/internal/core/agentruntime/plan.go` 扩展：

```go
type RetrievalPolicy string

const (
    RetrievalNone      RetrievalPolicy = "none"
    RetrievalOptional  RetrievalPolicy = "optional"
    RetrievalRequired  RetrievalPolicy = "required"
    RetrievalForbidden RetrievalPolicy = "forbidden"
)

type FreshnessLevel string

const (
    FreshnessNone   FreshnessLevel = "none"
    FreshnessLow    FreshnessLevel = "low"
    FreshnessMedium FreshnessLevel = "medium"
    FreshnessHigh   FreshnessLevel = "high"
)

type KnowledgePolicy struct {
    ContentType       string          `json:"contentType"`
    FreshnessLevel    FreshnessLevel  `json:"freshnessLevel"`
    RetrievalPolicy   RetrievalPolicy `json:"retrievalPolicy"`
    KnowledgeType     string          `json:"knowledgeType"`
    AllowedTools      []string        `json:"allowedTools,omitempty"`
    ForbiddenTools    []string        `json:"forbiddenTools,omitempty"`
    SearchQueries     []string        `json:"searchQueries,omitempty"`
    FreshnessDays     int             `json:"freshnessDays,omitempty"`
    MaxSearchResults  int             `json:"maxSearchResults,omitempty"`
    MustUseFacts      bool            `json:"mustUseFacts"`
    MustCiteFacts     bool            `json:"mustCiteFacts"`
    BlockOnEmptyFacts bool            `json:"blockOnEmptyFacts"`
}
```

然后把它挂到 `AgentPlan` 上：

```go
type AgentPlan struct {
    Goal            string           `json:"goal"`
    Domain          string           `json:"domain"`
    Mode            string           `json:"mode"`
    KnowledgePolicy *KnowledgePolicy `json:"knowledgePolicy,omitempty"`
    Steps           []AgentStep      `json:"steps"`
    Budget          AgentBudget      `json:"budget"`
    StopPolicy      StopPolicy       `json:"stopPolicy"`
}
```

## 5.2 新增 `KnowledgePolicyDecider`

```go
type Decider struct {
    llm LLMClient
}

func (d *Decider) Decide(ctx context.Context, req VideoRequest) (*KnowledgePolicy, error) {
    rulePolicy := DecideByRules(req.Topic)

    if rulePolicy.FreshnessLevel == FreshnessHigh {
        return rulePolicy, nil
    }

    // 对中间态再让 LLM 判断
    llmPolicy := d.decideByLLM(ctx, req)
    return MergePolicy(rulePolicy, llmPolicy), nil
}
```

合并原则：

```text
规则判断为 high freshness：LLM 不得降级
规则判断为 forbidden：LLM 不得启用 news_search
LLM 判断为 required：Guard 再复核关键词和任务类型
```

# 7. PlanGuard 改造方案

`PlanGuard` 当前已经校验步骤、工具、依赖、成本、风险、参数和阶段约束。([GitHub][4])
下一步要增加**知识策略校验**。

## 7.1 新增校验入口

```go
func (g *PlanGuard) ValidatePlan(ctx context.Context, userID string, plan *AgentPlan) error {
    if err := g.validateKnowledgePolicy(plan); err != nil {
        return err
    }

    // 原有校验逻辑继续保留
}
```

## 7.2 关键规则

### 规则 1：非新闻任务禁止新闻搜索

```go
func (g *PlanGuard) validateNewsSearchForbidden(plan *AgentPlan) error {
    kp := plan.KnowledgePolicy
    if kp == nil {
        return nil
    }

    if kp.RetrievalPolicy == RetrievalNone || kp.RetrievalPolicy == RetrievalForbidden {
        for _, step := range plan.Steps {
            if step.Tool == "news_search" {
                return fmt.Errorf("news_search is forbidden by retrievalPolicy=%s", kp.RetrievalPolicy)
            }
        }
    }

    return nil
}
```

### 规则 2：高时效任务必须检索

```go
func (g *PlanGuard) validateHighFreshnessRequiresSearch(plan *AgentPlan) error {
    kp := plan.KnowledgePolicy
    if kp == nil {
        return nil
    }

    if kp.FreshnessLevel == FreshnessHigh {
        if kp.RetrievalPolicy != RetrievalRequired {
            return fmt.Errorf("high freshness task requires retrievalPolicy=required")
        }

        if !hasTool(plan, "news_search") {
            return fmt.Errorf("high freshness task requires news_search")
        }

        if !hasTool(plan, "fact_extractor") {
            return fmt.Errorf("high freshness task requires fact_extractor")
        }
    }

    return nil
}
```

### 规则 3：required 检索必须阻断空事实

```go
func (g *PlanGuard) validateBlockOnEmptyFacts(plan *AgentPlan) error {
    kp := plan.KnowledgePolicy
    if kp == nil {
        return nil
    }

    if kp.RetrievalPolicy == RetrievalRequired && !kp.BlockOnEmptyFacts {
        return fmt.Errorf("required retrieval must set blockOnEmptyFacts=true")
    }

    return nil
}
```

# 8. PlanCompiler 改造方案

`PlanCompiler` 当前负责将步骤转成 DAG，并可自动注入质量检查节点。([GitHub][5])
下一步要让它支持**知识节点自动插入**。

## 8.1 编译前补全知识步骤

```go
func (c *PlanCompiler) Compile(plan *AgentPlan) (*model.DAGRequest, error) {
    plan = c.injectKnowledgeSteps(plan)

    // 原有 injectQualityGates / applyDirectors / compileStep 保留
}
```

## 8.2 自动插入逻辑

```go
func (c *PlanCompiler) injectKnowledgeSteps(plan *AgentPlan) *AgentPlan {
    kp := plan.KnowledgePolicy
    if kp == nil {
        return plan
    }

    if kp.RetrievalPolicy != RetrievalRequired && kp.RetrievalPolicy != RetrievalOptional {
        return plan
    }

    if hasTool(plan, "news_search") {
        return plan
    }

    knowledgeSearch := AgentStep{
        ID:     "knowledge_search",
        Intent: "搜索与当前视频主题相关的最新事实",
        Tool:   "news_search",
        Arguments: map[string]interface{}{
            "queries":       kp.SearchQueries,
            "freshnessDays": kp.FreshnessDays,
            "topK":          kp.MaxSearchResults,
        },
        ExpectedOutput: []string{"results"},
    }

    factExtract := AgentStep{
        ID:        "fact_extract",
        Intent:    "将搜索结果整理为事实包",
        Tool:      "fact_extractor",
        DependsOn: []string{"knowledge_search"},
        Arguments: map[string]interface{}{
            "searchResults": "{{knowledge_search.output.results}}",
            "outputMode":    "fact_pack",
        },
        ExpectedOutput: []string{"facts", "sources", "warnings", "freshness"},
        ProduceArtifact: true,
    }

    plan.Steps = prependSteps(plan.Steps, knowledgeSearch, factExtract)

    for i := range plan.Steps {
        if plan.Steps[i].Tool == "video_script_generator" {
            plan.Steps[i].DependsOn = appendIfMissing(plan.Steps[i].DependsOn, "fact_extract")
            plan.Steps[i].Arguments["knowledgePack"] = "{{fact_extract.output.facts}}"
            plan.Steps[i].Arguments["knowledgeSources"] = "{{fact_extract.output.sources}}"
            plan.Steps[i].Arguments["retrievalPolicy"] = string(kp.RetrievalPolicy)
            plan.Steps[i].Arguments["mustUseFreshKnowledge"] = kp.MustUseFacts
        }
    }

    return plan
}
```

这样即使 Planner 漏掉了知识节点，Compiler 也能补齐。

```go
func ValidateScriptInput(input ScriptInput) error {
    if input.RetrievalPolicy == "required" && len(input.KnowledgePack.Facts) == 0 {
        return fmt.Errorf("fresh knowledge required but knowledgePack is empty")
    }

    if input.MustUseFreshKnowledge && len(input.KnowledgePack.Facts) == 0 {
```

## 10.3 Prompt 增加硬规则

```text
你是视频口播脚本生成器。

1. 如果提供了 knowledgePack，必须优先使用其中的事实。
```

# 11. 固定 Pipeline 与自主规划如何共存

你现在 `guided-image-text-video.yaml` 已经有清晰的人工审核阶段，并且 metadata 里明确 `requireReviewGates: true`、`allowFullAuto: false`、`humanApprovalStages` 包含 proposal、script、composition、preview。([GitHub][6])

所以第一版不要废弃固定 pipeline，而是做成：

```text
自主规划只负责前置知识策略和工具选择
固定 pipeline 继续负责视频生产主链路
```

## 推荐做法

```text
Planner 生成 KnowledgePolicy
  ↓
Compiler 根据 KnowledgePolicy 动态插入 knowledge_search / fact_extract
  ↓
后续仍走 proposal / script / composition / preview / render / package
```

也就是：

```text
动态前置段 + 稳定视频生产段
```

而不是：

```text
完全自由 Agent 自己规划所有节点
```

# 13. 缓存与旧知识污染处理

## 13.1 缓存 key 必须改变

错误缓存 key：

```text
topic + durationSec + stage
```

正确缓存 key：

```text
topic + durationSec + stage + retrievalPolicy + knowledgePackHash + currentDate
```

代码示意：

```go
func BuildScriptCacheKey(input ScriptInput) string {
    base := fmt.Sprintf("%s:%d:%s:%s",
        input.Topic,
        input.DurationSec,
        input.Stage,
        input.RetrievalPolicy,
    )

    if input.KnowledgePackHash != "" {
        base += ":" + input.KnowledgePackHash
    }

    base += ":" + time.Now().Format("2006-01-02")

    return sha256Hex(base)
}
```

否则你会遇到：

```text
搜索到了新事实
但脚本生成命中了旧缓存
最后仍然返回旧口播
```

# 15. 日志与 Trace 方案

每次运行必须记录：

```json
{
  "runId": "...",
  "topic": "...",
  "knowledgePolicy": {
    "freshnessLevel": "high",
    "retrievalPolicy": "required",
    "knowledgeType": "latest_news"
  },
  "plannedTools": ["news_search", "fact_extractor", "video_script_generator"],
  "executedTools": ["news_search", "fact_extractor", "video_script_generator"],
  "knowledgePackHash": "sha256:xxx",
  "factCount": 4,
  "sourceCount": 2,
  "scriptUsedFactCount": 3,
  "blockedReason": null
}
```

失败时：

```json
{
  "blockedReason": "retrievalPolicy=required but fact_extractor returned empty facts"
}
```

这样问题会非常清晰：

```text
是 Planner 没规划？
是 Guard 删掉了？
是搜索失败？
是事实抽取失败？
是脚本生成没消费？
是缓存命中旧结果？
```

# 17. 分阶段落地计划

## 第一阶段：修复“新闻没注入”的核心问题

目标：让新闻类口播必定走检索。

任务：

```text
1. AgentPlan 增加 KnowledgePolicy
2. 新增 KnowledgePolicyDecider
3. PlanGuard 增加新闻检索强制规则
4. PlanCompiler 自动插入 knowledge_search / fact_extract
5. video_script_generator 增加 knowledgePack 入参
6. E2E 验证佛得角案例
```

验收标准：

```text
佛得角案例不再返回旧稿
trace 中能看到 news_search 和 fact_extract
script 输出 usedFacts
required 搜索失败时阻断生成
```

---

## 第二阶段：避免非新闻内容被搜索污染

目标：让非新闻任务不调用新闻搜索。

任务：

```text

3. Planner Prompt 明确 news_search 使用边界
4. 增加 20 条分类测试样例
```

验收标准：

```text
观点类口播不调用 news_search
历史故事不调用 news_search
创意故事不调用 news_search
普通国家介绍不强制新闻搜索
```

---

## 第三阶段：可观测性与审核体验

目标：让你能快速定位“为什么没用新闻”。

任务：

```text
1. trace 增加 knowledgePolicy
2. trace 增加 plannedTools / executedTools
3. trace 增加 knowledgePackHash / factCount / usedFactCount
4. 前端审核页展示事实包
5. Review Gate 支持查看 usedFacts
```

验收标准：

```text
每次运行都能看到：
- 是否判断为新闻类
- 是否调用搜索
- 搜索返回多少事实
- 脚本用了哪些事实
```

---

## 第四阶段：质量门禁增强

目标：减少事实错误和旧知识污染。

任务：

```text
1. script_quality_checker 增加 fact consistency 检查
2. 检查 script 中是否出现 knowledgePack 外的强事实

```

验收标准：

```text
佛得角 required 检索时，脚本不能写“差点出线”
新闻类脚本不能脱离事实包编造比分、排名、日期
```

# 19. 最终结论

下一步优化不要只做“把 news_search 加到 pipeline 里”。那样会带来两个新问题：

```text
新闻类可能好了
非新闻类会被新闻污染
```

正确方向是：

```text
把“是否需要检索”升级为 AgentPlan 的核心字段
```

最终系统应形成这套机制：

```text
Planner 负责判断和规划
Guard 负责约束和拒绝错误规划
Compiler 负责把知识步骤插入 DAG
FactExtractor 负责把新闻变成事实包
ScriptGenerator 负责基于事实包生成口播
Trace 负责证明它确实用了事实
Review Gate 负责人工把关
```

第一版最小闭环只需要完成 6 件事：

```text
1. AgentPlan 增加 KnowledgePolicy
2. 新增 KnowledgePolicyDecider
3. PlanGuard 增加检索规则
4. PlanCompiler 自动插入 knowledge_search / fact_extract
5. video_script_generator 消费 knowledgePack
6. trace 输出 usedFacts / knowledgeTrace
```

这版做完后，你的视频 Agent 就会从：

```text
固定流程脚本生成器
```

升级成：

```text
能自主判断是否需要外部知识的受限规划型视频 Agent
```
