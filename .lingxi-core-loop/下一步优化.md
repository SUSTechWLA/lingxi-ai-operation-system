## 0. 当前状态判断

你这次更新已经完成了几项关键基础：

1. `Config` 里已经加入 `HyperFramesConfig`，并且有 `HYPERFRAMES_MODE / SERVICE_URL / TIMEOUT / FPS / OUTPUT_ROOT` 等默认值，之前的配置编译风险基本解决。([GitHub][1])

# 1. 当前最大缺口

## 缺口 1：`hyperframes_project_generator` 已注册，但没有真实执行分发

`skillcap.yaml` 已经声明了 `hyperframes_project_generator`，但 `video_creation_external_tools.go` 的本地工具列表和 switch 分发里仍然是旧的 `hyperframes_project_builder`，没有看到 `hyperframes_project_generator` 的执行分支。当前 switch 只把 `hyperframes_project_builder / storyboard_assembler` 分发到 `executeHyperframesProjectBuilder(...)`，而 `hyperframes_renderer` 分发到 `executeHyperframesRenderer(...)`。([GitHub][6])

这意味着：

```text id="eelvcn"
LLM Planner 可以规划 hyperframes_project_generator
但 Worker 可能无法真正生成项目
最后会落到 default placeholder 或执行失败
```

这是 P0。

---

## 缺口 2：旧 `executeHyperframesProjectBuilder` 仍然依赖 CLI

当前 `executeHyperframesProjectBuilder` 会先 `detectHyperFramesCLI()`，然后尝试通过 `runHyperFramesCommand(...)` 构建项目；失败后返回 guidance。([GitHub][6])

这和你的目标冲突：

```text id="75sqsz"
目标：不用 CLI
当前：项目构建阶段仍然优先找 CLI
```

渲染阶段已经有 Render Service，但项目生成阶段还没有完成服务化 / 本地 Go 原生生成。

---

## 缺口 3：渲染仍保留 CLI fallback

`executeHyperframesRenderer` 现在服务优先，这是对的；但当服务不可用时，它仍然会进入 legacy CLI fallback，并调用 `detectHyperFramesCLI()`。([GitHub][6])

当前代码里仍然存在对 `hyperframes` 和 `npx` 的 PATH 检测。([GitHub][6])

如果你要做“当前阶段不用 CLI”的版本，应改成：

```text id="pzymlv"
HYPERFRAMES_MODE=service
  → 服务不可用直接失败
  → 不再 fallback CLI

HYPERFRAMES_MODE=disabled
  → 不渲染，只生成创作包
```

---

## 缺口 4：`/render/stream` 还不是真正流式进度

`server.ts` 已经暴露 `/render/stream`，但当前实现是 `await renderVideo(...)` 后才发送 `complete`，所以它还不是持续推送真实进度。([GitHub][7])

第一版可以先不用 `/render/stream`，用 `/render + /jobs/:jobId` 或同步结果即可。但如果前端显示进度条，就需要后续改成真正异步 job。

---

## 缺口 5：Snapshot 仍是 Phase 2 能力

`server.ts` 的注释已经标记 `/snapshot` 是 Phase 2，当前可以先不作为上线阻塞项。([GitHub][7])

第一版上线链路可以是：

```text id="ttdi8c"
project_generator
  ↓
linter
  ↓
用户审核 HTML 项目
  ↓
renderer
```

Snapshot 可以下一阶段补。

# 4. P1：增强服务能力

## P1-1：真正实现 `/render/stream`

当前 `/render/stream` 是等 `renderVideo` 完成后一次性发 `complete`。([GitHub][7])

应改成异步 job：

```text id="1ihbns"
POST /render/stream
  ↓
创建 jobId
  ↓
后台 goroutine / promise 执行 render
  ↓
每 1 秒读取 queue progress
  ↓
SSE 推送 status
  ↓
complete / failed
```

### 目标 SSE

```text id="6o2srq"
event: status
data: {"jobId":"render_001","status":"preparing","progress":0}

event: status
data: {"jobId":"render_001","status":"rendering","progress":35}

event: status
data: {"jobId":"render_001","status":"encoding","progress":88}

event: complete
data: {"jobId":"render_001","outputPath":"/data/.../final.mp4"}
```

---

## P1-2：Go Client 增加 `RenderStream`

当前 Go Client 只有 `Health / Render / Lint`。([GitHub][5])

新增：

```go id="cu8vgi"
func (c *Client) RenderStream(

    onEvent func(RenderProgress),

```

Worker 收到进度后写入：
