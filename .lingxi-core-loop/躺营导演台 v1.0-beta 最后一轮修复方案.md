# 3. P0-1：固化 LocalJob artifacts[] 协议

## 3.1 标准协议

所有 local executor 返回的 artifacts[] 必须使用统一结构：

```json
{
  "unitId": "final-video",
  "kind": "VIDEO",
  "name": "final.mp4",
  "storageType": "local",
  "storageRef": "local://projects/{projectId}/renders/final.mp4",
  "mimeType": "video/mp4",
  "sizeBytes": 123456,
  "status": "valid",
  "humanApproved": false,
  "dependsOn": [
    "PREVIEW_SNAPSHOTS",
    "HYPERFRAMES_PROJECT"
  ],
  "producedByTool": "hyperframes_renderer",
  "producedByRole": "渲染制片",
  "metadata": {
    "renderTimeMs": 12345,
    "fps": 30,
    "width": 1920,
    "height": 1080,
    "localPath": "/absolute/path/to/final.mp4"
  }
}
```

## 3.2 必填字段

```text
unitId
kind
name
storageType
storageRef
status
humanApproved
dependsOn
producedByTool
producedByRole
metadata
```

## 3.3 各 executor 的 unitId 规范

| Local Command                | Artifact Kind       | unitId              |
| ---------------------------- | ------------------- | ------------------- |
| HYPERFRAMES_PROJECT_GENERATE | HYPERFRAMES_PROJECT | hyperframes-project |
| HYPERFRAMES_SNAPSHOT         | PREVIEW_SNAPSHOTS   | preview-snapshots   |
| HYPERFRAMES_RENDER           | VIDEO               | final-video         |
| FFMPEG_PROBE                 | FFMPEG_PROBE_REPORT | ffmpeg-probe-report |
| FINAL_REVIEW                 | FINAL_REVIEW        | final-review        |
| ARTIFACT_PACKAGE             | PROJECT_PACKAGE     | project-package     |

## 3.4 本轮要求

逐个检查以下文件：

```text
local-backend/internal/localtool/hyperframes_project_generate.go
local-backend/internal/localtool/hyperframes_snapshot.go
local-backend/internal/localtool/hyperframes_render.go
local-backend/internal/localtool/ffmpeg_probe.go
local-backend/internal/localtool/artifact_package.go
```

确认所有 `artifacts[]` 都满足协议。

# 4. P0-2：Cloud callback 必须使用严格 materializer

## 4.1 当前目标

LocalJob completion 后，Cloud 必须：

```text
1. 读取 node output
2. 调用 BuildArtifactRequestsFromNodeChecked
3. 如果 artifacts[] 合法，写入 ArtifactIndex
4. 如果 artifacts[] 不合法，标记 LocalJob / Node 失败或记录明确错误
```

禁止继续使用会吞掉错误的旧方法作为生产路径。

## 4.2 正确逻辑

LocalJob callback 中应类似：

```go
requests, err := artifact.BuildArtifactRequestsFromNodeChecked(projectID, workflowRunID, node)
if err != nil {
    if artifact.IsArtifactManifestInvalid(err) {
        // 1. 标记 LocalJob artifact sync failed
        // 2. 写 EventStream
        // 3. 写 DecisionLog 或 system error log
        // 4. 返回明确错误
        return fmt.Errorf("artifact sync failed: %w", err)
    }
    return err
}

for _, req := range requests {
    if _, err := artifactService.CreateArtifact(ctx, req); err != nil {
        return err
    }
}
```

## 4.3 错误码

如果 manifest 不合法：

```json
{
  "code": "ARTIFACT_MANIFEST_INVALID",
  "message": "本地任务返回的产物清单不完整，缺少 unitId 或 kind。",
  "nodeId": "render_exec",
  "localJobId": "local_job_xxx"
}
```

前端默认展示：

```text
本地任务返回的产物信息不完整，无法写入项目产物库。
请重新执行该步骤，或查看高级错误信息。
```

高级详情展示：

```text
错误码：ARTIFACT_MANIFEST_INVALID
节点：render_exec
原因：artifact unitId is required
```

# 8. P1：前端最终配合

前端不需要大改，只需要确保最终视频展示依赖 ArtifactIndex。

## 8.1 导出页展示条件

导出页只有在后端返回：

```json
{
  "kind": "VIDEO",
  "status": "valid",
  "storageRef": "local://projects/project-1/renders/final.mp4"
}
```

时显示：

```text

导出 package
打开项目文件夹
```

否则显示：

```text
最终视频尚未生成
```

## 8.2 错误提示

如果后端返回：

```text
ARTIFACT_MANIFEST_INVALID
```

前端展示：

```text
本地任务返回的产物信息不完整，无法写入项目产物库。
请重新执行该步骤。
```

高级详情里展示：

```text
错误码：ARTIFACT_MANIFEST_INVALID
```

## 8.3 不要前端自行推断 final.mp4

前端不要根据本地路径猜测 final.mp4 是否存在。必须以 ArtifactIndex 的 `VIDEO` artifact 为准。

