# 躺营导演台 v1.0-beta 发布前最后修正方案

## 1. 修正目标

当前版本主流程已经基本闭合：

```text
用户一句话
  ↓
方案 / 脚本 / 卡片 / 结构 / 预览
  ↓
人工审核
  ↓
本地 HyperFrames 渲染
  ↓
VIDEO artifact 写入 ArtifactIndex
  ↓
ffmpeg_probe
  ↓
final_review
  ↓
package
  ↓

```

本轮最后修正目标：

```text
1. 避免关键产物写入失败后系统仍显示任务成功
2. 用测试证明 LocalJob completed 后 VIDEO artifact 能进入 ArtifactIndex
3. 修正 workflowRunID 和 taskID 混用，保证后续审计、追踪、重跑稳定
```

完成后版本可定义为：

```text
躺营导演台 v1.0-beta
第一版小范围用户内测版
```

# 2. P0：关键 Artifact 写入失败不能静默继续

## 2.1 当前风险

当前 LocalJob 完成后，会同步 `output.artifacts[]` 到 Cloud ArtifactIndex。

风险点是：

```text
CreateArtifact 失败时，如果只是 warn + continue，
LocalJob 仍可能显示 completed，
但 ArtifactIndex 没有关键产物。
```

这会导致：

```text
本地 final.mp4 已生成
  ↓
VIDEO artifact 写入失败
  ↓
Cloud 不知道 final.mp4 存在
  ↓
前端导出页显示“最终视频尚未生成”
  ↓
用户无法理解问题
```

正式内测版不能允许这种“关键产物丢失但任务成功”的状态。

---

## 2.2 关键产物定义

以下 artifact 写入失败必须中断同步流程：

```text
VIDEO
FFMPEG_PROBE_REPORT
FINAL_REVIEW
PROJECT_PACKAGE
```

原因：

| Artifact            | 为什么关键                |
| ------------------- | -------------------- |
| VIDEO               | 最终成片，没有它导出页无法工作      |
| FFMPEG_PROBE_REPORT | 视频体检结果，没有它无法质量判断     |
| FINAL_REVIEW        | 最终质量门禁，没有它不能 package |
| PROJECT_PACKAGE     | 最终交付包，没有它无法交付        |

非关键 artifact 可以继续 warn，但也要记录错误。

## 2.4 修改 syncArtifactsFromLocalJob

位置：

```text

```


改成：

```go
for _, req := range requests {
	created, err := artifactSvc.CreateArtifact(ctx, req)
	if err != nil {
		logger.Warn("artifact sync: failed to create artifact",
			zap.String("projectID", projectID),
			zap.String("workflowRunID", workflowRunID),
			zap.String("taskID", taskID),
			zap.String("nodeID", node.ID),
			zap.String("kind", string(req.Kind)),
			zap.String("unitID", req.UnitID),

			zap.Error(err),

			return fmt.Errorf(
				"critical artifact sync failed: nodeID=%s kind=%s unitID=%s: %w",
				node.ID,
				req.Kind,
				req.UnitID,
				err,
			)
		}

		continue
	}

	logger.Info("artifact sync: created artifact",
		zap.String("projectID", projectID),
		zap.String("workflowRunID", workflowRunID),
		zap.String("taskID", taskID),
		zap.String("nodeID", node.ID),
		zap.String("artifactID", created.ID),
		zap.String("kind", string(created.Kind)),
		zap.String("unitID", created.UnitID),
	)
}
```

## 2.5 返回错误后的状态处理

如果关键 artifact sync 失败，建议至少做一件事：

```text
LocalJob completed 不能继续被认为是完整成功。
```

可选实现方式：

### 方案 A：标记 artifact sync failed

如果现有 local job 表支持 metadata，写：

```json
{
  "artifactSyncStatus": "failed",
  "artifactSyncError": "critical artifact sync failed: kind=VIDEO",
  "failedArtifactKind": "VIDEO"
}
```

### 方案 B：直接将对应 DAG node 标记失败

如果现有状态机支持 node failed，则：

```text
render node → failed
reason → critical artifact sync failed
```

### 方案 C：不改状态机，只返回错误并记录 EventLog

如果当前改状态机成本高，第一版至少要：

```text
1. callback 返回 error
2. 日志明确记录 localJobId / nodeId / artifactKind
3. 前端能看到“产物同步失败”
```

正式建议：

```text
第一版用方案 C 即可；
后续 beta.1 再把 artifactSyncStatus 做成正式状态字段。
```

## 3.3 建议抽取 ArtifactSyncService

新增：

```go
type ArtifactSyncService struct {
	artifactService *Service
	nodeRepo        NodeRepository
	logger          *zap.Logger
}

func NewArtifactSyncService(
	artifactService *Service,
	nodeRepo NodeRepository,
	logger *zap.Logger,
) *ArtifactSyncService {
	return &ArtifactSyncService{
		artifactService: artifactService,
		nodeRepo:        nodeRepo,
		logger:          logger,
	}
}
```

核心方法：

```go
func (s *ArtifactSyncService) SyncFromNodeOutput(
	ctx context.Context,
	projectID string,
	workflowRunID string,
	taskID string,
	node *model.Node,
) ([]*Artifact, error) {
	requests, err := BuildArtifactRequestsFromNodeChecked(projectID, workflowRunID, node)
	if err != nil {
		return nil, err
	}

	createdArtifacts := make([]*Artifact, 0, len(requests))

	for _, req := range requests {
		req.TaskID = taskID
		req.WorkflowRunID = workflowRunID

		created, err := s.artifactService.CreateArtifact(ctx, req)
		if err != nil {
			s.logger.Warn("artifact sync failed",
				zap.String("projectID", projectID),
				zap.String("workflowRunID", workflowRunID),
				zap.String("taskID", taskID),
				zap.String("nodeID", node.ID),
				zap.String("kind", string(req.Kind)),
				zap.String("unitID", req.UnitID),
				zap.Error(err),
			)

			if IsCriticalArtifactKind(req.Kind) {
				return createdArtifacts, fmt.Errorf(
					"critical artifact sync failed: kind=%s unitID=%s: %w",
					req.Kind,
					req.UnitID,
					err,
				)
			}

			continue
		}

		createdArtifacts = append(createdArtifacts, created)
	}

	return createdArtifacts, nil
}
```

`main.go` 里的 callback 只负责调用这个 service：

```go
artifactSyncService.SyncFromNodeOutput(
	ctx,
	projectID,
	workflowRunID,
	taskID,
	node,
)
```

这样测试会简单很多。

# 4. P1：修正 workflowRunID / taskID 混用

## 4.1 当前风险

当前 artifact sync 中可能存在：

```go
WorkflowRunID: taskID
TaskID: taskID
```

这对第一版主流程可能不阻断，因为很多查询按：

```text
projectID + stage + kind
```

但后续会影响：

```text
1. 按 run 查询产物
2. 多次重跑对比
3. 审计追踪
4. 失败恢复
5. 同项目多 workflow run
```

建议这次顺手修掉。

---

## 4.2 正确字段含义

```text
projectID：视频项目 ID
workflowRunID：本次工作流运行 ID
taskID：业务任务 ID / agent task ID
nodeID：DAG 节点 ID
```

不要混用。

---

## 4.3 CreateArtifactRequest 赋值规则

```go
req.ProjectID = projectID
req.WorkflowRunID = workflowRunID
req.TaskID = taskID
req.ProducedByNode = node.ID
```

不要再写：

```go
req.WorkflowRunID = taskID
```

---

## 4.4 callback 参数要求

LocalJob completion callback 必须能拿到：

```text
projectID
workflowRunID
taskID
nodeID
```

如果当前 callback 只有 taskID，则需要通过 `nodeID` 或 `taskID` 查询 `workflowRun`：

```go
run, err := workflowRunRepo.FindByTaskID(ctx, taskID)
if err == nil && run != nil {
	workflowRunID = run.ID
}
```

如果查不到，第一版可以 fallback，但要明确 warn：

```go
if workflowRunID == "" {
	logger.Warn("artifact sync: workflowRunID missing, fallback to taskID",
		zap.String("taskID", taskID),
		zap.String("nodeID", node.ID),
	)
	workflowRunID = taskID
}
```

但最终目标是：

```text
不 fallback，必须有真实 workflowRunID。
```

```text
6. go test ./cloud-backend/... 通过。

```

# 10. 最终结论

当前主链路已经成立。最后一轮不是功能开发，而是失败链路硬化：

```text
LocalJob completed
  ↓
关键 artifacts[] 写入 ArtifactIndex
  ↓
如果 VIDEO / FINAL_REVIEW / PROJECT_PACKAGE 写入失败，必须显式失败
  ↓
前端不能假装成功
  ↓
用户能看到明确错误并重新执行
```

修完后，系统才不会出现“本地任务成功但云端产物丢失”的隐性故障。这个问题补齐后，就可以作为正式第一版小范围用户内测版。
