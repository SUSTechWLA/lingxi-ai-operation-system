# 躺营导演台 v1.0 用户内测版升级解决方案

## 0. 版本目标

当前版本定位：

```text
躺营导演台 v1.0-alpha2
第一版用户内测候选版
```

升级目标：

```text
躺营导演台 v1.0-beta
第一版小范围用户内测版
```

本次升级不新增大功能，重点做 5 件事：

```text
1. 产物状态可信
2. 审核结果可信
3. 上游修改后下游必然过期
4. 预览未确认绝不能渲染
5. 一句话到 final.mp4 的真实链路可验收
```

第一版内测只支持：

```text
中文图文视频
16:9
45-90 秒
HyperFrames 本地渲染
分阶段确认
本地 final.mp4 导出
项目 package 打包
```

第一版内测不做：

```text
Seedance 动态视频
TTS 自动配音
ASR 自动字幕
平台自动发布
多人协作审批
多模型路由
复杂素材库
商业权限体系
```

# 1. 当前系统差距总结

当前系统已经具备：

```text
1. 躺营导演台前端主界面
2. 十角色 Agent 定义
3. PlanGuard / StageGuard
4. PlanCompiler 审核节点注入
5. 审核 API：通过 / 驳回 / 修改 / 重新生成
6. LocalJob 分发
7. HyperFrames 本地执行器
8. 结构级 v1 E2E
9. Artifact 模型字段初步补齐
10. RenderDependencyChecker 初步接入
```

但离用户内测还有 5 个硬差距：

```text
P0-1：Artifact 字段虽然有，但仓储持久化和查询还没有完全对齐
P0-2：StaleTracker 仍偏提示，不是系统事务
P0-3：RenderDependencyChecker 偏 payload 校验，不是数据库事实校验
P0-4：LocalJob 完成后的产物状态同步还需要标准化
P0-5：E2E 仍偏结构级测试，缺真实运行级验收
```

---

# 2. 总体升级架构

升级后系统应形成 4 条硬链路：

```text
用户审核链路：
Review Gate → approve/reject/edit/regenerate → ArtifactReview → DecisionLog → ArtifactIndex

产物治理链路：
ArtifactCreated → ArtifactIndex → DependencyGraph → StaleTracker → DownstreamBlocked

本地执行链路：
NodeExecutor → RenderDependencyGuard → LocalJob → LocalBackend → ArtifactMetadataSync

最终交付链路：
HYPERFRAMES_RENDER → FFMPEG_PROBE → FINAL_REVIEW → PACKAGE_GUARD → ARTIFACT_PACKAGE
```

核心原则：

```text
1. 前端只展示状态，不负责判断状态
2. LLM 可以建议流程，但不能绕过系统门禁
3. Tool 可以生成产物，但产物是否可用由 ArtifactIndex 决定
4. Review 可以改变状态，但必须写 DecisionLog
5. Render 必须由数据库事实确认后才能开始
```

# 3. P0-1：ArtifactIndex 持久化硬化

## 3.1 问题

当前 Artifact 模型已经有这些字段：

```text
Status
HumanApproved
DependsOn
ProducedByNode
ProducedByTool
ProducedByRole
RoleAgentID
TaskID
UpdatedAt
```

但仓储 SQL 仍主要读写旧字段，导致这些字段可能只在内存或 metadata 中存在，不一定成为稳定事实源。

这会带来风险：

```text
1. 重启后 status 丢失
2. humanApproved 只能从 metadata 推断
3. dependsOn 无法稳定用于 StaleTracker
4. RenderDependencyGuard 无法完全依赖 ArtifactIndex
```

## 3.2 目标

ArtifactIndex 必须成为第一版内测事实源。

每个产物必须能回答：

```text
这个产物是什么？
由哪个阶段生成？
由哪个角色生成？
由哪个工具生成？
依赖哪些上游产物？
当前是否有效？
是否已经人工确认？
是否可被下游使用？
```

# 5. P0-3：RenderDependencyGuard 升级为数据库事实校验

## 5.1 当前状态

当前 NodeExecutor 已有 RenderDependencyChecker，并在本地渲染前调用。这个方向是对的。

但默认检查主要依赖 payload：

```text
previewApproved
previewHumanApproved
videoCompositionStatus
hyperframesProjectStatus
```

payload 可以由计划或节点参数提供，不是最终可信事实。

## 5.2 目标

渲染前必须从数据库读取真实状态：

```text
VIDEO_COMPOSITION_SPEC
HYPERFRAMES_PROJECT
PREVIEW_SNAPSHOTS
artifact_reviews
local runner capability
```

只要任何条件不满足，禁止创建 LocalJob。

## 5.3 新增 RepositoryBackedRenderDependencyChecker

```go
type RepositoryBackedRenderDependencyChecker struct {
    artifactService *artifact.Service
    reviewStore     ArtifactReviewStore
    runnerRegistry  localrunner.Registry
}

func (c *RepositoryBackedRenderDependencyChecker) CheckRenderDependencies(
    ctx context.Context,
    req RenderDependencyCheckRequest,
) error {
    if req.Command != localrunner.CommandHyperFramesRender &&
       req.ToolName != "hyperframes_renderer" {
        return nil
    }

    missing := []string{}

    composition := c.findCurrentArtifact(ctx, req.ProjectID, "VIDEO_COMPOSITION_SPEC")
    if composition == nil || composition.Status != "valid" {
        missing = append(missing, "视频结构无效或已过期")
    }
    if composition != nil && !composition.HumanApproved {
        missing = append(missing, "视频结构尚未确认")
    }

    project := c.findCurrentArtifact(ctx, req.ProjectID, "HYPERFRAMES_PROJECT")
    if project == nil || project.Status != "valid" {
        missing = append(missing, "渲染项目不存在或已过期")
    }

    preview := c.findCurrentArtifact(ctx, req.ProjectID, "PREVIEW_SNAPSHOTS")
    if preview == nil || preview.Status != "valid" {
        missing = append(missing, "预览快照不存在或已过期")
    }
    if preview != nil && !preview.HumanApproved {
        missing = append(missing, "预览尚未确认")
    }

    if !c.hasApprovedReview(ctx, req.ProjectID, "preview") {
        missing = append(missing, "预览审核未通过")
    }

    if !c.runnerSupports(ctx, req.ProjectID, localrunner.CommandHyperFramesRender) {
        missing = append(missing, "本地执行器未就绪或不支持渲染")
    }

    if len(missing) > 0 {
        return RenderDependencyError{
            Code: "RENDER_DEPENDENCY_MISSING",
            Message: "当前项目尚不满足最终渲染条件",
            Missing: missing,
        }
    }

    return nil
}
```

## 5.4 接入方式

启动 worker 时注入：

```go
nodeExecutor.SetRenderDependencyChecker(
    NewRepositoryBackedRenderDependencyChecker(
        artifactService,
        artifactReviewStore,
        localRunnerRegistry,
    ),
)
```

保留 DefaultRenderDependencyChecker 作为无数据库场景 fallback，但生产和内测环境必须使用 repository-backed checker。

## 5.5 前端规则

如果条件不满足，前端不显示“开始渲染”，只显示：

```text
预览确认后可开始渲染
```

如果用户强行触发，后端返回：

```json
{
  "code": "RENDER_DEPENDENCY_MISSING",
  "message": "当前项目尚不满足最终渲染条件",
  "missing": [
    "预览尚未确认",
    "视频结构已过期"
  ]
}
```

# 6. P0-4：FinalReview 与 PackageGuard

## 6.1 目标

不能只要 render 成功就允许导出。

必须形成：

```text
最终视频生成
  ↓
ffmpeg_probe
  ↓
final_review_generator
  ↓
FINAL_REVIEW.passed = true
  ↓
artifact_packager
```

```json
{
  "passed": true,
  "summary": "视频文件存在，时长、分辨率、视频流、文件大小均符合要求。",
  "checks": {
    "fileExists": true,
    "fileSizeValid": true,
    "durationValid": true,
    "resolutionValid": true,
    "hasVideoTrack": true,
    "hasReadableMetadata": true,
    "packageReady": true

  "video": {
    "path": "local://projects/{projectId}/final/final.mp4",
    "durationSec": 45,
    "width": 1920,
    "height": 1080,
    "fps": 30,
    "sizeBytes": 123456789
  },
  "blockingIssues": [],
  "warnings": []
}
```

## 6.3 PackageGuard

`artifact_packager` 执行前必须检查：

```text
VIDEO.status = valid
```

# 15. 最终结论

当前系统已经不需要继续大改架构。

下一步应该做的是：

```text
从“Agent 架构可用”
升级为
“用户内测状态可信”
```

最关键的 3 条红线：

```text
1. 上游修改，下游必须 stale。
2. 预览未确认，绝不能渲染。
3. 质量未通过，绝不能打包。
```

完成本方案后，系统可以作为：

```text
躺营导演台 v1.0-beta
第一版小范围用户内测版
```
