## 四、正向手工验收流程

完整跑一遍真实链路：

```text
1. 启动 cloud-backend
2. 启动 local-backend
3. 启动 hyperframes-render-service
4. 启动 frontend
5. 输入一句话需求：
   “请帮我做一个45秒中文图文视频，讲智能体改变的是工作流”
6. 审核通过创意方案
7. 审核通过视频脚本
8. 审核通过卡片分镜
9. 审核通过视频结构
10. 生成预览
11. 审核通过预览
12. 开始 HYPERFRAMES_RENDER
13. 本地生成 final.mp4
14. Cloud ArtifactIndex 出现 VIDEO
15. VIDEO.unitId = final-video
16. VIDEO.status = valid
17. VIDEO.storageRef 指向 final.mp4
18. 执行 ffmpeg_probe
19. 生成 FFMPEG_PROBE_REPORT
20. final_review.passed = true
21. package 成功生成 PROJECT_PACKAGE
22. 导出页显示 final.mp4
23. package 中包含 final.mp4
```

## 五、反向手工验收流程

必须验证以下失败场景：

```text
[ ] 预览未确认时不能 render
[ ] local runner offline 时不能 render
[ ] VIDEO 不存在时不能 package
[ ] final_review.passed=false 时不能 package
[ ] artifacts[] 缺 unitId 时不能静默成功
[ ] VIDEO 写入失败时不能显示任务完整成功
[ ] 修改脚本后 preview / video / final_review / package stale
```

## 六、前端错误提示验收

触发或 mock 以下错误码，确认前端中文提示正确：

```text
CRITICAL_ARTIFACT_SYNC_FAILED
→ 关键产物写入失败，最终视频无法进入项目产物库。请重新执行当前步骤。

ARTIFACT_MANIFEST_INVALID
→ 本地任务返回的产物信息不完整，无法写入项目产物库。请重新执行当前步骤。

RENDER_DEPENDENCY_MISSING
→ 当前项目尚不满足最终渲染条件，请确认预览、本地执行器和前置产物状态。

PACKAGE_DEPENDENCY_MISSING
→ 最终视频尚未通过质量检查，暂时不能打包。
```

同时确认高级详情展示：

```text
[ ] 错误码
[ ] 节点ID
[ ] 产物类型
[ ] 单元ID
[ ] 原始错误
```

## 七、可选优化：补真实 repository 级集成测试

当前 fake creator 级测试已经足够支撑第一版小范围内测。

如果有 Postgres 测试环境，可以新增：

```go

```

测试目标：

```text
ArtifactSyncService
  ↓
artifact.Service.CreateArtifact
  ↓
artifact.Repository
  ↓
FindCurrentByStageAndKind(projectID, "render", "VIDEO")
```

断言：

```go
video, err := artifactRepo.FindCurrentByStageAndKind(ctx, projectID, "render", "VIDEO")

require.NoError(t, err)
require.NotNil(t, video)
require.Equal(t, "final-video", video.UnitID)
require.Equal(t, artifact.KindVideo, video.Kind)
require.Equal(t, "valid", video.Status)
require.Equal(t, "local://projects/project-1/renders/final.mp4", video.StorageRef)
require.Equal(t, "run-1", video.WorkflowRunID)
require.Equal(t, "task-1", video.TaskID)
```

如果当前测试环境没有 DB 容器，不强制做。

## 八、可选优化：增加 GitHub Actions CI

新增 `.github/workflows/beta-ci.yml`：

```yaml
name: v1.0-beta-ci

on:
  push:
    branches:
      - develop_go_back
  pull_request:
    branches:
      - develop_go_back

jobs:
  cloud-backend:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-go@v5
        with:
          go-version: '1.23'
      - name: Test cloud backend
        run: go test ./cloud-backend/...

  local-backend:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-go@v5
        with:
          go-version: '1.23'
      - name: Test local backend
        run: go test ./local-backend/...

  frontend:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: '20'
      - name: Build frontend
        working-directory: frontend
        run: |
          npm ci
          npm run build
```

如果项目实际 Go 版本不是 1.23，请按 `go.mod` 调整。
