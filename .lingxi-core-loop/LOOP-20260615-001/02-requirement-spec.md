# 02-Requirement-Spec: 自动化标书生成 — 需求规格

## 业务背景

企业投标需要大量重复性文档工作：阅读招标文件、提取评分要求、匹配企业资质、撰写技术方案、排版导出。当前依赖人工完成，效率低、容易遗漏关键评分项。

AIOS 平台需要提供自动化标书生成能力，帮助用户快速产出高质量标书。

## 用户角色

| 角色 | 职责 |
|------|------|
| 投标专员 | 上传招标文件、配置标书参数、审核生成结果、导出标书 |
| 审核人 | 人工审核标书章节、给出修订意见 |
| 系统管理员 | 管理企业资料库、标书模板、合规规则 |

## 核心需求

### REQ-001: 招标文件上传与解析
用户上传招标文件（PDF/Word/图片），系统自动解析文档内容，提取：
- 项目基本信息（名称、编号、预算、截标日期）
- 技术要求和规格
- 评分项和评分标准
- 资质要求
- 投标文件格式要求

### REQ-002: 标书结构智能规划
基于解析的招标要求，LLM 自动生成标书目录结构和章节规划，包括：
- 章节标题和子章节
- 每个章节对应哪些评分项
- 每个章节需要的企业资料类型
- 章节优先级和依赖关系

用户可调整、增删章节。

### REQ-003: 企业资料智能匹配
系统从企业资料库中检索和匹配：
- 公司资质证书和许可证
- 过往项目案例和经验
- 技术团队和人员简历
- 财务数据和报表
- 标准化的技术方案模板

匹配结果关联到标书各章节。

### REQ-004: AI 章节内容生成
对每个标书章节，基于：
- 招标文件中的技术要求
- 匹配到的企业资料
- 标书写作规范和模板
- 用户自定义的写作风格和关键词

LLM 生成完整的章节内容，包括文本、表格、图表描述。

### REQ-005: 合规检查
对生成的标书内容进行多维度检查：
- 评分项覆盖率（是否遗漏评分要求）
- 格式合规（字体、字号、页边距、页数限制）
- 内容合规（不出现竞争对手名称、敏感词等）
- 完整性检查（所有必填章节是否已填写）

### REQ-006: 人工审核干预
在关键节点提供人工审核：
- 章节规划审核：确认标书结构
- 内容审核：逐章节审核 AI 生成内容
- 终稿审核：整体检查后批准导出

审核通过后工作流继续，驳回则带修订意见返回生成节点。

### REQ-007: 标书导出
将审核通过的标书导出为 Word 文档（.docx）：
- 保留格式（标题层级、表格、图片位置）
- 自动生成封面和目录
- 支持自定义页眉页脚
- 可选的 PDF 导出

### REQ-008: 进度追踪与历史管理
- 实时查看标书生成进度（当前阶段、完成百分比）
- 标书版本管理（保存多版本草稿）
- 操作历史追溯（谁在什么时间做了什么操作）
- 历史标书查询和复用

## 验收标准 (AC)

### REQ-001 验收
- AC-001-1: 支持上传 PDF、DOCX、图片格式招标文件
- AC-001-2: 解析准确率 > 90%（评分项提取）
- AC-001-3: 50 页招标文件解析时间 < 30 秒
- AC-001-4: 解析失败时给出明确错误提示

### REQ-002 验收
- AC-002-1: 自动生成标书目录结构，人工可编辑
- AC-002-2: 每个章节关联对应的评分项
- AC-002-3: 章节规划生成时间 < 60 秒

### REQ-004 验收
- AC-004-1: AI 生成内容与招标要求相关（非通用模板）
- AC-004-2: 支持对单章节重新生成
- AC-004-3: 生成内容长度符合标书规范（不空洞不冗余）
- AC-004-4: 单章节生成时间 < 120 秒

### REQ-005 验收
- AC-005-1: 评分项覆盖率检查：列出未覆盖的评分项
- AC-005-2: 检查结果可点击跳转到对应章节
- AC-005-3: 检查时间 < 30 秒

### REQ-006 验收
- AC-006-1: 审核操作（通过/驳回）在 3 次点击内完成
- AC-006-2: 驳回时审核意见可附加到对应章节
- AC-006-3: 审核状态变更实时通知

### REQ-007 验收
- AC-007-1: 导出 .docx 文件，格式完整
- AC-007-2: 包含自动生成的封面和目录
- AC-007-3: 导出时间 < 60 秒

### REQ-008 验收
- AC-008-1: 进度页面显示当前阶段和百分比
- AC-008-2: 支持查看历史标书列表
- AC-008-3: 支持从历史版本恢复

## 非功能性需求 (NFR)

- NFR-001: 完整标书生成全流程时间 < 60 分钟（500 页以内）
- NFR-002: 系统支持 10 个并发标书生成任务
- NFR-003: 数据持久化，服务重启后任务不丢失
- NFR-004: API 响应格式统一使用 `{code, message, data}` 信封
- NFR-005: 所有操作有 Trace ID，可追踪完整链路

## 风险 (RISK)

- RISK-001: 招标文件格式多样，解析准确率难以保证
- RISK-002: LLM 生成内容可能存在"幻觉"，需要人工审核兜底
- RISK-003: 企业敏感数据安全（资质证书等）
- RISK-004: 标书生成时间较长（数十分钟），需要可靠的异步执行
- RISK-005: 不同行业标书规范差异大，模板化难度高
