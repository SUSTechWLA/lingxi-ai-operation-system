# 03-Acceptance-and-NFR: 验收标准与非功能需求

## Core 准入检查

根据 Skill 定义，Core 更新必须满足：

1. ✅ 属于编排、工具治理、日志或中间件视频创作职责
2. ✅ 不包含具体业务规则
3. ✅ 可被多个场景复用（标书生成、视频分析、大数据处理等）
4. ✅ 无法通过外部 Tool、Workflow 或配置合理实现
5. ✅ 有稳定边界（Node 模型扩展，状态机扩展）
6. ✅ 可自动测试
7. ✅ 有兼容、迁移和回滚方案

## 测试策略

### 单元测试
- 状态机新增转换（RUNNING → HEARTBEAT_TIMEOUT → RECOVERING）
- 进度聚合计算
- 心跳超时检测逻辑

### 集成测试
- 完整的"长任务创建 → 进度上报 → 心跳维持 → 完成"流程
- Checkpoint 保存和恢复流程
- 心跳超时 → 自动重试流程

### 回归测试
- 所有现有短任务测试必须通过
- 现有状态转换测试必须通过

### 性能测试
- 100 个并发长任务节点的心跳扫描性能
- 进度查询延迟验证

## 验证命令

```bash
cd aios-core
go fmt ./...
go vet ./...
go test ./... -count=1
go test -race ./... -count=1
```

## 发布与回滚

### 数据库迁移
- 新增列通过 ALTER TABLE ADD COLUMN IF NOT EXISTS
- 回滚：无需回滚新增列（默认值兼容）

### 配置变更
- 新增配置项有默认值
- 不修改已有配置项

### 行为回滚
- 如果长任务功能出现问题，不声明 long_running 的节点行为完全不受影响
