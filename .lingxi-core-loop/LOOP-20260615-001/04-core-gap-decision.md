# 04-Core-Gap-Decision: Core Gap 决策

## 决策流程

```
配置能否解决？
→ 否，进度追踪/心跳/checkpoint 需要代码级支持

已有 Workflow 能否解决？
→ 否，Workflow 模板只能编排已有能力，不能添加新能力

是否只缺外部 Tool？
→ 否，这是编排层的通用能力缺失

是否只需 Route、Prompt、模板或 UI？
→ 否，需要内核状态机和数据模型变更

是否只需前端 client 新页面？
→ 否，需要后端 API 和内核机制

剩余缺口是否属于通用平台机制？
→ 是
```

## 结论

**CORE_CHANGE_CANDIDATE**

## Core 准入条件验证

| 条件 | 判定 | 说明 |
|------|------|------|
| 属于通用职责 | ✅ | 编排层的进度/心跳/恢复是所有长任务的通用需求 |
| 不包含业务规则 | ✅ | 不涉及标书、合同、内容等具体业务 |
| 可多场景复用 | ✅ | 标书生成、视频处理、大数据分析等 |
| 无法用外部 Tool 实现 | ✅ | 心跳/状态机是编排层核心机制 |
| 有稳定边界 | ✅ | Node 模型扩展 + 状态机扩展 |
| 可自动测试 | ✅ | 单元测试 + 集成测试 |
| 有兼容回滚方案 | ✅ | 新旧字段兼容，短任务行为不变 |

## 执行决策

```yaml
decision: CORE_CHANGE_CANDIDATE
core_write_enabled: true
```
