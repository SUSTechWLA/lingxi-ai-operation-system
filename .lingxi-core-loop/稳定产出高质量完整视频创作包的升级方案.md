# 稳定产出高质量完整视频创作包的升级方案

## 0. 当前判断

你现在的系统已经有动态 Agent 主链路：`Runner.Start()` 会执行 `Planner → Guard → Compiler → Orchestrator`，并把 `AgentPlan` 编译成临时 DAG 后提交给 Orchestrator。这个方向是正确的。([GitHub][1])

但目前要稳定产出高质量视频创作包，仍有三个核心短板：

1. **核心视频 Prompt Tool 没完全接入真实 LLM 执行**
   当前动态 prompt tool 列表只包含 `knowledge_researcher / fact_checker / publish_copy_generator / video_package_exporter`，不包含 `video_script_generator / shot_splitter / video_prompt_generator`。这会导致口播稿、分镜、视频 Prompt 这三个核心环节可能落到占位输出。([GitHub][2])

2. **LLM Planner 还只是“可用”，不是“稳定”**
   当前 `LLMPlanner` 已经能检索候选工具、调用 LLM、解析 JSON 并输出 `AgentPlan`，但主要依赖 Prompt 约束和 JSON 提取，还缺少强 JSON Schema、修复回路、质量门和更严格 Guard。([GitHub][3])

3. **Guard 只做了基础校验**
   当前 `PlanGuard` 检查空计划、重复 step、工具存在、必填参数、成本、side effect 审核和简单依赖顺序，但还缺参数类型、引用字段、风险等级、质量门和下游产物审核约束。([GitHub][4])

所以现在的目标不是继续大改架构，而是把这条主链路做实：

```text
LLM Planner
  ↓
PlanGuard
  ↓
PlanCompiler
  ↓
Prompt Tool 真实执行
  ↓
Quality Gate
  ↓
Artifact Review
  ↓
Package Export
```

# 1. 最终产物标准：什么叫“完整视频创作包”

先把“高质量完整视频创作包”定义清楚。否则 Agent 会输出一堆文本，但不知道是否完整。

一个完整视频创作包至少应包含：

```text
video_project_package/
├── 00_project_brief.md              # 项目说明
├── 01_knowledge_research.md         # 知识资料整理
├── 02_fact_check.md                 # 事实核查报告
├── 03_oral_script.md                # 口播稿
├── 04_shot_list.json                # 分镜结构化列表
├── 05_shot_list.md                  # 分镜可读版
├── 06_keyframe_prompts.md           # 关键帧提示词
├── 07_video_prompts.md              # 视频生成提示词
├── 08_publish_copy.md               # 标题、简介、标签
├── 09_quality_report.md             # 质量检查报告
└── package_manifest.json            # 机器可读索引
```

其中 `package_manifest.json` 应该是最终交付索引：

```json
{
  "projectTitle": "端午节的来历：为什么我们要过端午？",
  "topic": "端午节的来历",
  "platform": "小红书",
  "language": "zh-CN",
  "aspectRatio": "16:9",
  "targetDurationSec": 90,
  "artifacts": [
    {
      "kind": "KNOWLEDGE_RESEARCH",
      "name": "01_knowledge_research.md",
      "reviewStatus": "APPROVED"
    },
    {
      "kind": "SCRIPT",
      "name": "03_oral_script.md",
      "reviewStatus": "APPROVED"
    },
    {
      "kind": "SHOT_LIST",
      "name": "04_shot_list.json",
      "reviewStatus": "APPROVED"
    },
    {
      "kind": "VIDEO_PROMPTS",
      "name": "07_video_prompts.md",
      "reviewStatus": "APPROVED"
    }
  ],
  "quality": {
    "passed": true,
    "score": 87
  }
}
```

```text

  ↓

  ↓

  ↓
shot_splitter
  ↓

  ↓

  ↓
video_prompt_generator
  ↓
video_prompt_quality_checker
  ↓
publish_copy_generator
  ↓
video_package_exporter
  ↓
package_quality_checker
```

不是每次都必须全部调用，但默认高质量模式建议走完整链路。

# 3. P0 修复：让核心 Prompt Tool 真正执行

## 3.1 修复 `isDynamicAgentPromptTool`

当前只识别四个动态 prompt tool，缺少三个核心工具。([GitHub][2])

必须改为：

```go
func isDynamicAgentPromptTool(toolName string) bool {
    switch toolName {
    case "knowledge_researcher",
        "fact_checker",
        "video_script_generator",
        "shot_splitter",
        "keyframe_prompt_generator",
        "video_prompt_generator",
        "publish_copy_generator",
        "video_package_exporter",
        "script_quality_checker",
        "shot_quality_checker",
        "video_prompt_quality_checker",
        "package_quality_checker":
        return true
    default:
        return false
    }
}
```

这一步是最高优先级。否则 Agent Planner 再聪明，后面的核心工具也可能只是占位输出。

---

## 3.2 给每个 Prompt Tool 独立 Prompt

当前 `buildDynamicAgentSystemPrompt` 只给 `knowledge_researcher / fact_checker / publish_copy_generator / video_package_exporter` 写了专门 Prompt，其它工具会落到默认通用 Prompt。([GitHub][2])

必须补齐：

```go
case "video_script_generator":
    return `你是短视频口播稿创作专家...`

case "shot_splitter":
    return `你是短视频分镜导演...`

case "keyframe_prompt_generator":
    return `你是AI图像关键帧提示词导演...`

case "video_prompt_generator":
    return `你是AI视频生成提示词导演...`

case "script_quality_checker":
    return `你是口播稿质量审核员...`

case "shot_quality_checker":
    return `你是分镜质量审核员...`

case "video_prompt_quality_checker":
    return `你是视频生成提示词质量审核员...`

case "package_quality_checker":
    return `你是视频创作包最终质检员...`
```

不要再让这些核心阶段使用通用 prompt。

| `video_package_exporter`    | all artifacts                   | package                 | 必须   |

## 4.2 质量检查工具

必须新增这四个：

| 工具                             | 检查对象      | 作用                                 |
| ------------------------------ | --------- | ---------------------------------- |
| `script_quality_checker`       | 口播稿       | 检查结构、节奏、时长、知识准确性、开头吸引力             |
| `shot_quality_checker`         | 分镜        | 检查 shot 数量、每镜头 3-15 秒、画面连续性        |
| `video_prompt_quality_checker` | 视频 Prompt | 检查每个 prompt 是否可生成、是否包含镜头运动、主体动作、转场 |
| `package_quality_checker`      | 最终包       | 检查是否缺文件、未审核、字段缺失、格式错误              |

质量检查工具不一定都需要用户审核，但必须能触发自动返工。

# 9. PlanGuard 增强方案

当前 Guard 已经检查工具存在、必填参数、成本和依赖顺序。([GitHub][4])

需要增强：

## 9.1 参数类型校验

```go
func validateParameterTypes(step AgentStep, manifest *tool.ToolManifest) error {
    for name, value := range step.Arguments {
        def, ok := manifest.Parameters[name]
        if !ok {
            continue
        }
        if isReferenceExpression(value) {
            continue // 引用在运行时解析，先跳过，后续做引用类型校验
        }
        if !matchesParamType(value, def.Type) {
            return fmt.Errorf("step %s parameter %s type mismatch: want %s", step.ID, name, def.Type)
        }
    }
    return nil
}
```

---

## 9.2 引用合法性校验

检查：

```text
{{script_generation.output.script}}
```

必须满足：

```text
script_generation 是上游 step
script 是该工具 output 中声明的字段
```

---

## 9.3 风险等级校验

```go
if riskRank(manifest.RiskLevel) > riskRank(plan.Budget.MaxRiskLevel) {
    return fmt.Errorf("step %s uses risk level %s above allowed %s", ...)
}
```

# 11. Artifact Review 闭环

目前 CONTROL 审核可复用，但长期应升级成产物审核。CONTROL 节点 READY 后暂停任务的能力已经存在。([GitHub][5])

建议落地：

```text
TOOL 输出 artifacts
  ↓
ArtifactStore 保存
  ↓
artifact_reviews 插入 PENDING
  ↓
CONTROL 节点引用 reviewId
  ↓
用户 approve
  ↓
artifact_reviews = APPROVED
  ↓
CONTROL node SUCCESS
  ↓
下游继续
```

未审核产物禁止进入下游：

```text
如果 argument 引用了上游 artifact
且 artifact.reviewRequired = true
且 reviewStatus != APPROVED
则 Worker 不执行
```

# 最终结论

你当前系统已经有动态 Agent 骨架，下一步要解决的不是“还能不能规划”，而是：

```text
规划出来的每个工具是否真实高质量执行
每个中间产物是否结构化
每个关键节点是否有质量检查
每个核心产物是否审核后才进入下游
最终包是否有固定交付标准
```

一句话：

> **把视频 Agent 从“能跑通动态流程”升级为“每一步都有 Schema、Prompt、质量门、审核门和导出标准”的生产级内容生成流水线。**
