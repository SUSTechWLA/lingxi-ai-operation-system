# 躺营导演台 v1.0 用户内测版对齐方案

## 1. 目标定义

第一版用户内测版不是技术 demo，而是一个用户能完整完成视频项目的产品版本。

内测版必须支持：

```text
一句话启动视频项目
  ↓
多角色 Agent 分工
  ↓
创意方案审核
  ↓
脚本审核
  ↓
卡片/分镜审核
  ↓
视频结构审核
  ↓
预览审核
  ↓
本地渲染确认
  ↓
final.mp4 生成
  ↓
质量检查
  ↓
打包导出
```

产品命名统一为：

```text
躺营导演台
AI 多角色视频创作工作台
```

第一版只做：

```text
中文图文视频
16:9
HyperFrames 本地渲染
分阶段人工确认
本地 final.mp4 导出
```

第一版不做：

```text
Seedance 动态视频
TTS 自动配音
ASR 自动字幕
平台自动发布
多人协作审批
复杂素材库
```

---

## 2. 当前版本主要差距

当前后端已经较完整，但距离用户内测还差以下关键项：

```text
P0-1：前端仍未对齐“躺营导演台”最终产品体验
P0-2：缺少真正的躺营导演台 v1 E2E 测试
P0-3：ArtifactIndex 还不是完整事实源
P0-4：StaleTracker 没有硬接入 submit-edited / regenerate / reject
P0-5：RenderDependencyGuard 没有成为运行时硬门禁
P0-6：用户修改产物后的下游阻断和 UI 提示不完整
P0-7：final.mp4 生成、质检、打包、前端预览需要完整验收
```

# 5. P0：ArtifactIndex 升级为事实源

## 5.1 ArtifactRecord 必须补字段

当前 artifact 模块已有版本管理，但用户内测需要更明确的状态字段。

建议新增：

```go
type ArtifactRecord struct {
    ID              string
    ProjectID       string
    WorkflowRunID   string
    TaskID          string
    StageName       string
    RoleAgentID     string

    Kind            string
    Name            string
    Version         int
    StorageType     string
    StorageRef      string

    Status          string // valid / stale / rejected / failed / deleted
    IsCurrent       bool
    HumanApproved   bool
    DependsOn       []string

    ProducedByNode  string
    ProducedByTool  string
    ProducedByRole  string

    Metadata        map[string]interface{}
    CreatedAt       time.Time
    UpdatedAt       time.Time
}
```

如果不想改表结构，也必须至少把这些字段稳定写入 `metadata`，并在 API 输出时提升为顶层字段。

---

## 5.2 ArtifactIndex API

新增或确认：

```http
GET /api/video-projects/:id/artifacts
GET /api/artifacts/:id
GET /api/artifacts/:id/content
GET /api/artifacts/:id/history
POST /api/artifacts/:id/revise
POST /api/artifacts/:id/mark-stale
POST /api/artifacts/:id/approve
```

---

## 5.3 Artifact 写入规则

```text
Tool 成功 → 写 ArtifactRecord
Review 通过 → humanApproved=true
Review 驳回 → status=rejected 或 stale
用户修改 → 新 version，旧 version 非 current
重新生成 → 新 version，下游 stale
渲染失败 → VIDEO status=failed
```

# 7. P0：RenderDependencyGuard 硬门禁

## 7.1 检查点

创建 `HYPERFRAMES_RENDER` LocalJob 前必须检查：

```text
VIDEO_COMPOSITION_SPEC exists && valid && humanApproved
HYPERFRAMES_PROJECT exists && valid
PREVIEW_SNAPSHOTS exists && valid && humanApproved
preview_review.status == APPROVED
local runner online
HYPERFRAMES_RENDER available
FFMPEG_PROBE available
disk enough
```

---

## 7.2 接入位置

必须三层阻断：

```text
PlanGuard：计划阶段禁止明显非法 render
NodeExecutor：创建 LocalJob 前再次检查真实状态
Frontend：preview 未通过不显示“开始渲染”
```

---

## 7.3 失败响应

{

# 13. 最终判断

当前 develop_go 已经是**非常接近第一版的工程候选版本**。它的后端 Agent Runtime、ToolManifest、RoleAgent、StageGuard、LocalJob 方向都已经对了。

但要成为“第一版用户内测版”，还必须补齐：

```text
前端品牌和用户体验
真实 v1 E2E
ArtifactIndex 状态治理
StaleTracker 硬接入
RenderDependencyGuard 运行时硬门禁
Resume/上下文压缩基础能力
```

一句话结论：

**当前版本不建议直接给用户内测；完成上面 P0 项后，可以作为“躺营导演台 v1.0 beta”进入第一批用户内测。**
