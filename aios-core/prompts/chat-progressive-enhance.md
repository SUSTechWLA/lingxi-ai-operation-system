# Skill：对话式创作渐进增强（保持设计连贯性）

## 一、概述
在当前发布页面基础上，将右上角的「AI生成全部内容」按钮增强为**智能对话生成入口**。用户点击后，在当前页面中央弹出一个对话式创作窗口（Modal），通过引导式问答补全信息后，自动生成标题、简介、正文、关键词并填入表单。同时，在右侧面板新增一个轻量级「AI助手」Tab，支持自然语言修改已生成的内容。

## 二、前置条件
1. 当前发布页面已存在：上传素材区、标题/简介/关键词输入框、平台选择器、「AI生成全部内容」按钮。
2. 后端 `PublishService` 已有 `AIGenerateContent()` 等方法，可基于素材和文字生成内容。
3. Zustand store 包含 `title`、`description`、`keywords`、`body`、`videos`、`images`、`platforms` 字段。
4. Redis 可用。

## 三、设计连贯性策略
| 当前页面元素 | 优化方式 |
|-------------|---------|
| 「AI生成全部内容」按钮 | **保留**，点击后弹出对话式生成 Modal，不跳页 |
| 右上角功能按钮区 | **不变**，仅 Modal 覆盖 |
| 右侧面板（平台选择） | 右侧面板新增一个「AI助手」Tab，与平台选择并列 |
| 标题/简介/关键词输入框 | **保留所有手动编辑能力**，AI 生成内容自动填入，用户可再手动修改 |
| 「AI润色」按钮 | **保留**，功能不变；右侧 AI 助手 Tab 中增加“自然语言修改”入口 |
| 整体布局 | **不增不减**，所有新功能以 Modal 或右侧 Tab 形式呈现 |

## 四、核心交互流程

### 场景 1：用户有模糊想法，无素材
1. 用户在当前页面点击「AI生成全部内容」按钮。
2. 弹出居中的**对话式生成 Modal**（宽度约 560px，与页面风格一致）。
3. Modal 顶部显示“告诉 AI 你的想法”，下方为对话消息列表。
4. AI 通过反问引导用户补充信息（如“你想写什么主题？”）。
5. 用户输入想法后，AI 继续引导询问：风格、目标平台、想传达的感受等。
6. 信息足够后，AI 自动生成：
   - 标题 → 填入标题输入框
   - 简介 → 填入简介输入框
   - 正文 → 填入正文编辑器（如存在）
   - 关键词 → 填入关键词输入框
7. Modal 关闭，用户可在表单中继续编辑。

### 场景 2：用户已有素材，想基于素材生成
1. 用户上传素材后，「AI生成全部内容」按钮可点击。
2. 点击后弹出 Modal，AI 自动识别已上传的素材，直接生成初版内容并填入表单，同时在 Modal 内展示生成摘要，用户可以继续对话微调。

### 场景 3：生成后自然语言修改
1. 用户在右侧面板切换到「AI助手」Tab。
2. 在此 Tab 内，用户可以输入自然语言修改指令（如“把标题改得更吸引人”、“简介缩短到50字”）。
3. AI 根据指令修改对应字段，并实时更新到左侧表单。
4. 此处不显示完整对话历史，仅保留最近的修改指令和结果，偏工具型轻交互。

## 五、后端实现

### 1. 新增端点 `POST /api/chat/generate`
**请求**：
```json
{
  "session_id": "optional",
  "message": "我想写一篇关于独自旅行的文章",
  "current_context": {
    "title": "",
    "description": "",
    "body": "",
    "keywords": [],
    "media_ids": []
  }
}
```
**响应 (HTTP 200)**：
```json
{
  "message": "success",
  "data": {
    "session_id": "session-abc",
    "reply": "太好了！你希望文章的风格是怎样的？",
    "suggestions": [
      {"text": "治愈温暖", "type": "style"},
      {"text": "干货攻略", "type": "style"}
    ],
    "fields": null
  }
}
```
当信息足够时，`fields` 包含生成结果：
```json
"fields": {
  "title": "一个人的旅行，遇见内心的平静",
  "description": "独自踏上旅途...",
  "body": "丽江古城的清晨...",
  "keywords": ["独自旅行", "内心平静"]
}
```

### 2. 新增端点 `POST /api/chat/revise`
**请求**：
```json
{
  "message": "把标题改得更吸引人",
  "current_fields": {
    "title": "一个人的旅行",
    "description": "...",
    "body": "...",
    "keywords": [...]
  }
}
```
**响应**：
```json
{
  "message": "success",
  "data": {
    "reply": "已将标题改为更具吸引力的版本",
    "fields": {
      "title": "独自上路，找到了真正的自己"
    }
  }
}
```

### 3. Service 逻辑
- `chat/generate`：基于会话历史 + 用户消息 + 系统提示词，调用大模型逐步收集信息，直到信息充足后生成完整内容。
- `chat/revise`：在大模型上下文中传入当前各字段内容，要求只修改用户指定部分，返回修改后的字段值。
- 会话状态存储在 Redis，TTL 30 分钟。

## 六、前端实现

### 1. 对话式生成 Modal
- 新建 `GenerateModal.tsx`，使用现有 Modal 或 Dialog 组件封装。
- 点击「AI生成全部内容」按钮时弹出。
- 内部结构：
  - 顶部标题：“AI 智能创作”
  - 中间消息列表（用户消息与 AI 回复，风格与现有 TailwindCSS 一致）
  - AI 回复中的建议选项渲染为可点击按钮（如“治愈温暖”）。
  - 底部输入框，支持 Enter 发送。
- 当响应中包含 `fields` 时，自动调用 Zustand store 方法更新标题、简介、正文、关键词，并关闭 Modal。

### 2. 右侧 AI 助手 Tab
- 在右侧面板上方增加两个 Tab：「发布平台」和「AI助手」。
- 「AI助手」Tab 内容：
  - 简短欢迎语：“输入修改指令，AI 帮你完善内容”。
  - 输入框，用户输入修改指令后发送。
  - 下方展示最近的修改记录（例如“标题已更新”）。
  - 操作按钮：“应用优化建议”（如有）。
- 调用 `POST /api/chat/revise`，返回 `fields` 后更新 Zustand store。

### 3. 状态管理
在 Zustand store 中增加：
```typescript
chatSessionId: string | null;
setChatSessionId: (id: string) => void;
// 修改方法（与 editTitle 等方法可合并）
applyFields: (fields: Partial<AppState>) => void;
```

### 4. 视觉一致性
- Modal 背景半透明深色遮罩，与现有 AI 加载遮罩风格一致。
- 消息气泡、输入框复用现有 TailwindCSS 类名。
- 风格建议按钮使用与平台选择器相同的色调和圆角。
- 右侧 Tab 切换样式与整个页面侧边栏/面板风格一致。

## 七、验收标准
1. 用户点击「AI生成全部内容」→ 弹出 Modal → 进行 2-4 轮对话 → 标题、简介、正文、关键词自动填入表单 → Modal 关闭。
2. 已上传素材时，AI 可直接生成初始内容，不需额外引导。
3. 在右侧「AI助手」Tab 输入修改指令，对应表单字段实时更新。
4. 原有「AI生成全部内容」按钮、AI润色按钮、平台选择等功能完全不受影响。
5. Web 端和 Electron 端均可正常使用，无布局错乱。
6. 所有操作可追溯，Context 审计正常。
