# Stage: recording_script

从观点档案生成 `source/口播稿.md`——纯录音用的口播稿件，用户可对照朗读录音。此文件仅服务于录音，不含任何视频制作指令。

## 输出格式

输出完整 Markdown 口播稿，结构如下：

```markdown
# 《<标题>》

## BEAT 01｜<功能描述>｜0—8秒

【<录音语气提示，不超过一行>】

<口播句子，使用 / 表示短停顿，// 表示长停顿>

【<可选强调说明>】

<继续口播，关键重音可用 **粗体**>

---
```

每个 BEAT 之后用 `---` 分隔。

## 默认说话风格

- **短视频强留存 + 真人聊天感**：像跟一个特定观众聊天，而非读正式文件
- 开场 3 秒内给出具体钩子，15 秒内亮明核心观点
- 每个 BEAT 至少有 1 个留存钩子：未回答的问题、小幅反转、具体细节、或前向牵引
- 自然对话连接词适度使用："你有没有发现"、"说白了"、"问题是"、"但这里有个关键点"、"我后来意识到"、"你会发现"
- 短句口语表达，而非完整书面段落
- 先具体场景后抽象概念：用一个生动故事/场景开头，再提炼观点

## BEAT 结构与时长

- 中文口播按每秒 4.5-5.5 字估算，根据语调节奏和停顿调整 BEAT 时长
- 每个 BEAT 标注起止时间，所有 BEAT 时长相加等于目标总时长
- BEAT 功能包括：开场钩子、具体场景、矛盾展开、论证推进、反方回应、情绪转折、结尾落点

## 录音标记规则

- `【语气】`：简短提示，如"像突然想到一个问题"、"稍微放松"、"认真起来"
- `/`：短停顿约 0.3-0.5 秒
- `//`：长停顿约 0.8-1.2 秒
- `**加粗**`：仅标记需要重读的关键词，不过度使用
- 段落不宜过长，让换气点自然

## 禁止事项

- 禁止包含任何画面/镜头/动画/字幕/素材等视频制作指令
- 禁止写成工整书面文章、报告或知识说明
- 禁止假亲近感：营销腔、过度金句、播音腔、强迫兴奋、空洞设问轰炸
- 禁止连续反问句堆砌
- 不添加"待补充"、"此处可发挥"等占位词
- 不输出 JSON 格式，输出纯粹口播稿 Markdown
