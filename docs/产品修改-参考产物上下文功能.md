# 产品修改：AI 修改产物时支持查看并引用其他产物作为上下文

> **版本**：v1.0 | **日期**：2025-07-08 | **状态**：计划中

---

## 1. 背景与动机

### 1.1 当前问题

在标书产物查看器（`BiaoshuArtifactViewer`）中修改产物时，AI 仅拿到**当前产物正文** + **用户修改指令** + **最近 10 条对话历史**，**无法参考同项目的其他产物**。

典型场景：用户希望微调「技术标大纲」（`BID_OUTLINE`），但大纲的各级标题应从「招标文件解析报告/评分表」（`BID_ANALYSIS`）中拆解评分项而来。缺少解析报告上下文时，AI 生成的大纲可能偏离评分标准。

### 1.2 目标

- 用户可以在产物查看器中选择同项目的其他产物作为「参考产物」，其内容随修改请求一并发送给 AI
- 参考产物默认全选，用户可按需取消勾选
- 参考内容**按需加载**，仅在发送修改请求时才读取文件，不做预加载

#### 3.3.3 修改 `buildReviseUserPrompt` 签名与实现

```go
// 位置：第 292-320 行

func buildReviseUserPrompt(
    artifactContent, userInstruction string,
    contextMessages []ReviseContextMessage,
    references []ReferenceArtifact,  // ⬅️ 新增参数
) string {
    var sb strings.Builder

    // ⬇️ 新增：参考产物
    if len(references) > 0 {
        sb.WriteString("## 参考产物（作为修改的参考依据）\n\n")
        sb.WriteString("以下是与当前产物同项目的其他产物，供你修改时参考：\n\n")
        for _, ref := range references {
            name := ref.Name
            if name == "" {
                name = ref.Kind
            }
            sb.WriteString(fmt.Sprintf("### %s\n\n", name))
            sb.WriteString(ref.Content)
            sb.WriteString("\n\n")
        }
        sb.WriteString("---\n\n")
    }

    sb.WriteString("## 当前产物内容\n\n")
    sb.WriteString(artifactContent)
    sb.WriteString("\n\n## 用户修改指令\n\n")
    sb.WriteString(userInstruction)

    // ...上下文部分不变...

    return sb.String()
}
```

func TestBuildReviseUserPromptWithReferences(t *testing.T) {
    content := "# 第三章大纲"
    instruction := "根据评分标准补充四级标题"
    refs := []ReferenceArtifact{
        {Kind: "BID_ANALYSIS", Name: "招标文件解析报告", Content: "评分项：施工组织方案(30分)"},
        {Kind: "BID_RAW_TEXT", Name: "原文解析", Content: "第三章 投标人须知"},
    }
    prompt := buildReviseUserPrompt(content, instruction, nil, refs)

    if !strings.Contains(prompt, "参考产物") {
        t.Error("prompt should contain reference section header")
    }
    if !strings.Contains(prompt, "施工组织方案(30分)") {
        t.Error("prompt should contain reference artifact content")
    }
    if !strings.Contains(prompt, "招标文件解析报告") {
        t.Error("prompt should contain reference artifact name")
    }
    if !strings.Contains(prompt, content) {
        t.Error("prompt should still contain current artifact content")
    }
}

func TestBuildReviseUserPromptWithoutReferences(t *testing.T) {
    content := "# 第一章"
    instruction := "优化"
    prompt := buildReviseUserPrompt(content, instruction, nil, nil)

    if strings.Contains(prompt, "参考产物") {
        t.Error("prompt should NOT contain reference section when references is nil")
    }
    if !strings.Contains(prompt, content) {
        t.Error("prompt should contain artifact content")
    }
}

## 4. 影响分析

### 4.1 对现有功能的影响

| 功能 | 影响 | 说明 |
|------|------|------|
| 修改无参考产物的产物 | **零影响** | `referenceArtifacts: undefined`，后端 `buildReviseUserPrompt` 中 `len(references) > 0` 为 false，prompt 不变 |
| 修改有参考产物的产物 | **功能增强** | 多选参考产物，发送时自动加载并嵌入 prompt |
| 产物列表页 | **零影响** | `peerArtifacts` prop 默认 `[]`，不影响现有表结构 |
| 历史对话加载 | **零影响** | 无改动 |
| 修订预览/应用/写回 | **零影响** | 无改动 |

### 4.2 Token 消耗

- 每勾选一个参考产物，其全文被嵌入 prompt，**增加对应 token 消耗**
- 参考产物上限：参考内容 + 当前产物 ≤ 500KB（后端校验）
- 建议：产品层面提示用户「参考产物过多会增加响应时间」

### 4.3 后端接口兼容性

- `referenceArtifacts` 是**可选字段**，旧版客户端不传 → 行为不变
- 后端新增字段，旧版客户端调用 → json 反序列化忽略未知字段 → **完全兼容**

## 6. 风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| 参考产物过多导致 500KB 超限 | 请求被后端拒绝 | 后端返回明确错误，前端展示"参考产物 + 当前产物总大小超限，请减少参考产物" |
| 参考产物读取失败 | 某个参考产物未被包含 | 静默跳过，其余正常发送 |
| UI 紧凑性问题 | 「参考产物」区占用对话面板空间 | 默认折叠，不干扰对话体验 |
| 大文档修改时 token 过多 | 响应变慢、费用增加 | 500KB 后端硬限制，产品引导用户仅勾选必要的参考产物 |
