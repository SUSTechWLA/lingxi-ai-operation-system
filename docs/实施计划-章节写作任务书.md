## 3. 详细设计

### 3.1 输出规范

`04_章节写作任务书.md` 应包含以下结构：

```markdown
# 章节写作任务书

## 项目信息
- 项目名称：xxx
- 生成时间：xxx

## 章节依赖关系图
（mermaid 或纯文本树形图）

## 1. 第一章 施工组织方案（示例）
{
  "chapterId": "ch01",
  "chapterTitle": "第一章 施工组织方案",
  "level": 1,
  "targetScoreItems": [
    { "item": "施工组织方案", "points": 30 }
  ],
  "inputArtifacts": [
    "00_招标文件原文解析.md",
    "00_招标文件解析报告.md",
    "02_评分标准拆解表.md"
  ],
  "writingFocus": "重点阐述施工总平面布置、施工顺序、关键线路进度计划...",
  "evidenceNeeds": [
    "施工区域划分图",
    "进度横道图/网络图",
    "总平面布置示意图"
  ],
  "forbiddenContent": [
    "不可出现报价、预算金额",
    "不可编造不存在的设备/人员"
  ],
  "estimatedWordCount": 5000,
  "dependencies": []
}

## 2. 第二章 质量管理体系与保证措施
...

1. 先写独立章节（无依赖）→ 第一章、第二章
2. 再写依赖多的章节 → 第三章

## 总字数预估
| 章节 | 预估字数 |
|------|----------|
| 第一章 | 5000 |
| ... | ... |
| **合计** | **45000** |
```

### 3.2 System Prompt

```text
你是一个专业的标书写作任务规划专家。请根据《技术标四级大纲》、《评分标准拆解表》
和《招标文件解析报告》，生成一份详细的章节写作任务书。

任务书必须：
1. 为每个一级章节拆解为独立的写作任务。
2. 每个章节任务必须包含：
   - chapterId: 章节唯一标识（如 ch01）
   - chapterTitle: 章节标题
   - level: 标题层级（1=一级 2=二级 3=三级 4=四级）
   - targetScoreItems: 该章节对应的评分项及分值列表
   - inputArtifacts: 撰写该章节时需要参考的产物文件
   - writingFocus: 3-5 个写作重点/策略建议（结合项目背景信息）
   - evidenceNeeds: 需要准备或引用的证明材料/图表清单
   - forbiddenContent: 该章节撰写时必须避开的内容
   - estimatedWordCount: 预估字数
   - dependencies: 依赖的章节 ID 列表
3. 评分项映射必须精确——每项评分标准至少被一个章节覆盖。
4. 预估字数总和应在 3-8 万字之间（根据评标标准调整）。
5. 不涉及报价章节——技术标不含商务报价内容。
6. 输出整洁的 Markdown，章节任务使用清晰的标题层级。
7. 在末尾补充写作顺序建议和总字数预估表。
```

## 6. 风险与边界

| 风险 | 缓解措施 |
|------|---------|
| 大纲输出格式不统一（LLM 风格差异） | 在 system prompt 中要求 task book 使用固定 JSON 段格式；不依赖大纲的 Markdown 解析 |
| 大纲过于庞大导致 token 不足 | `limitTextForPrompt(outline, 15000)` 截断 |
| 评分拆解表未生成（可选输入） | 允许为空，prompt 省略评分节 |
| 任务书生成质量差（遗漏评分项） | prompt 中强约束 "每项评分标准至少被一个章节覆盖" |
| 与后续批量写作的衔接 | 任务书 JSON 段结构为阶段 8 提供结构化输入 |
