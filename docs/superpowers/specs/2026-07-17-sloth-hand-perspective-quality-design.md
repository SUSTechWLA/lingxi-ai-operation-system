# Sloth Hand Perspective Quality Design

## Goal

修复主 IP 树懒在口播 Demo 2 到 3 秒抬臂后手指视觉突然放大、过厚和偏人类张手的问题，同时保证三指独立控制、动作可读性和正面 A-roll 构图。

## Verified Root Cause

问题可稳定复现在 `MainIP_Sloth_Refined_Aroll_Demo_1080p.mp4` 的 `Aroll_OpenPalm_Explain` 段落：

- 动作从 `2.27s` 开始，主要异常位于约 `2.5s–3.5s`。
- 手指及手掌骨骼矩阵缩放始终位于 `0.9999995–1.0000004`，不存在真实缩放关键帧。
- 工作室中景相机设计值为 `50mm`，运行时构图校准为了容纳全部手势，在固定机位上将焦距降到 `25mm`。
- 开放手势期间双手中心向镜头前移约 `0.29m`；右手屏幕面积从约 `0.00454` 增加至约 `0.00737`，增长约 `62%`。
- `open_hand` 外侧手指张角为 `±0.22rad`，手势语义接近人类张掌，不符合三趾树懒细长、低张角、末端内钩的轮廓。

因此修复必须同时处理自动构图和树懒手势语义。仅缩小手指或仅修改相机都不能消除其他动作中的同类风险。

## Design

### 1. Perspective-Safe Medium Camera

`Camera_Standing_Medium` 和 `Camera_Seated_Medium` 保留工作室设计的长焦观感。自动构图不再通过把焦距降到广角来容纳动作：

- 中景焦距不得低于 `48mm`。
- 首选保留设计焦距；构图不安全时沿相机局部视线轴后移相机。
- 后移过程中允许有限 `shift_y` 调整，但不得改变相机横向位置或朝向。
- 候选构图必须满足现有头部、左右手安全边距要求。
- 在满足安全边距的候选中，优先选择最接近设计焦距、最少后移和最少 shift 变化的结果。
- 校准报告记录设计/最终焦距、设计/最终位置、后移距离及逐帧边界。

这样可以保持同样取景范围，同时显著减少近距离广角对前伸手掌的透视放大。

### 2. Sloth-Specific Three-Digit Poses

三指仍保留三段骨骼和独立控制，但常用手势改为树懒语义：

- `open_hand`：外侧手指张角限制在约 `±0.08rad`；近端轻屈、中段和末端逐渐增加弯曲，形成自然内钩。
- `relaxed_hand`：维持当前细长轮廓，避免手腕处突然收缩。
- `count_three`：三指可辨认，但横向张角不得超过 `±0.12rad`。
- 挥手、解释、欢迎和双侧比较动作复用新的 `open_hand`，不单独复制参数。
- 握拳、捏合、单指计数继续保留独立语义，不通过全局缩放隐藏问题。

本轮不重建完整手掌拓扑，也不改变源模型身份特征。只有现有表面在新姿态下仍明显过厚时，才允许在生产副本上做有上限的末端径向收窄，并必须更新几何合同版本。

### 3. Production QA Gates

新增可重复的自动门禁：

- 所有手掌和手指骨骼在动作时间轴上的局部及矩阵缩放必须处于 `1.0 ± 0.001`。
- 中景相机最终焦距必须不低于 `48mm`。
- 开放解释动作相对动作前放松帧的单手屏幕面积增长不得超过 `35%`。
- 左右手在安全帧内完整可见，且不接触画面边界。
- `open_hand` 和 `count_three` 的外侧手指张角满足树懒姿态上限。
- 三根手指均能独立运动，张开、闭合、计数和挥手之间仍有可测像素差异。
- 2 到 3.5 秒生成逐帧接触表和高分辨率关键帧，供最终人工观感复核。

任何一项失败都不得发布新的主 Blend 或替换最终 Demo。

## Asset and Render Flow

1. 从现有 `main-ip-aroll-master-refined.blend` 创建非破坏性候选副本。
2. 使用更新后的代码重建动作库和生产时间轴。
3. 用工作室场景重新校准中景相机。
4. 先渲染 `2.0s–3.6s` 诊断片段并通过自动门禁。
5. 再渲染约 15 秒、`1920x1080`、`30fps` 的完整 Demo。
6. 对最终视频执行完整解码、帧率、重复帧、音频响度和关键帧视觉检查。
7. 只有全部通过后，生成新版本主 Blend 和最终 Demo，不覆盖唯一源文件。

## Error Handling

- 找不到设计中景相机、角色 Armature、三指骨骼或动作样本时立即失败。
- 在允许的后移范围内无法满足安全构图时失败，不回退到低于 `48mm` 的广角。
- 无法计算手部屏幕区域或报告样本不完整时失败。
- 生产渲染失败时保留旧主资产和旧 Demo，候选输出留在独立证据目录。

## Acceptance

- 2 到 3 秒抬臂后，手指不再产生突然放大感。
- 三根手指细长、低张角、末端自然内钩，整体仍保持当前卡通树懒风格。
- 双手解释动作完整可见，不穿模、不碰边、不遮挡面部。
- 正面镜头保持自然中景透视，角色与背景光照、材质和构图连续。
- 完整动作、口型、站姿和坐姿能力不回归。
- 新 1080p Demo 通过自动 QA、人工关键帧复核和媒体技术验收。

## Repository Follow-Up

本设计完成并验收后，再执行已确认的双层归档：

- 旧跟踪资产和历史 IP 内容进入独立远端归档分支。
- 本地生成物进入 Git 忽略的 `.workspace-archive/`，由一键清理脚本管理。
- `develop_go` 和重写后的 `release` 分支治理使用独立设计与提交，避免与模型修复互相污染。
